# 开发者使用手册

开发者负责将构建好的 Docker 镜像发布到应用商店的 **staging-project**（预发布项目），触发审核流程；审核通过后镜像自动同步到 **production-project**（生产项目），最终由用户通过 **部署控制台** 拉取并部署容器。

## 1. 发布流程总览

```text
开发者推送镜像到 staging-project（预发布）
        │
        ▼
自动创建审核记录（状态：待审核）
        │
        ▼
管理员审核
   ├─ 通过 → 镜像自动复制到 production-project（生产）
   └─ 拒绝 → 镜像不会进入生产
        │
  production-project ◀── 用户通过部署控制台拉取部署
```

## 2. 前置条件

- 本机已安装 **Docker**。
- 已获得镜像仓库（`192.168.41.227:8097`）的登录凭证。
- 已被管理员添加到对应项目的 **开发者（Developer）** 角色。

## 3. 镜像命名规则

```text
192.168.41.227:8097/<项目名称>/<应用名称>:<版本号>
```

示例：

| 目标                   | 地址                                                       |
| ---------------------- | ---------------------------------------------------------- |
| 预发布（推送）         | `192.168.41.227:8097/staging-project/happy_chat:V1.0.0`    |
| 生产（审核后自动同步） | `192.168.41.227:8097/production-project/happy_chat:V1.0.0` |

**版本号规范**：推荐语义化版本号，如 `V1.0.0`、`V1.0.0-beta`、`V1.0.0-rc.1`。

## 4. 查看推送命令

管理后台提供推送命令查询功能：

1. 进入 **应用管理 → 项目管理**。
2. 点击项目名称进入 **应用仓库**。
3. 在目标仓库行点击 **推送命令** 按钮（上传图标）。
4. 弹窗展示操作步骤与命令，支持一键复制。

## 5. 登录 → 打标签 → 推送

```bash
# 1. 登录镜像仓库
docker login 192.168.41.227:8097

# 2. 构建镜像（或从已有镜像打标签）
docker build -t happy_chat:latest .
# 或: docker tag <已有镜像> happy_chat:latest

# 3. 打标签（推送到 staging-project，触发审核）
docker tag happy_chat:latest 192.168.41.227:8097/staging-project/happy_chat:V1.0.0

# 4. 推送
docker push 192.168.41.227:8097/staging-project/happy_chat:V1.0.0
```

推送完成后：

- 后台会自动创建一条**待审核**审核记录（同一仓库 + 同一 Tag 不会重复创建）。
- 请联系管理员在 **应用审核** 中审核。
- 审核通过后镜像自动复制到 **production-project**，此时可被拉取部署。

> 提示：`staging-project` 只作为推送入口；请勿直接向 `production-project` 推送镜像。

## 6. 部署控制台（用户拉取与部署）

用户通过独立的 **部署控制台** 浏览应用、拉取镜像并管理容器，地址为 `http://<部署控制台地址>:3002`。

### 6.1 登录

1. 打开浏览器访问 `http://<部署控制台地址>:3002`。
2. 填写登录信息：

| 字段         | 说明           | 示例                         |
| ------------ | -------------- | ---------------------------- |
| 应用商店地址 | 镜像仓库地址   | `http://192.168.41.227:8097` |
| 用户名       | 镜像仓库用户名 | `zhangzexin`                 |
| 密码         | 镜像仓库密码   | `********`                   |

3. 点击「执行 docker login」，后端自动登录并创建会话。

### 6.2 浏览应用列表

登录后 **应用列表** 展示所有可用镜像（来自 production-project）：

| 内容     | 说明                          |
| -------- | ----------------------------- |
| 镜像名称 | `项目名/应用名`               |
| 标签     | 版本号（Tags），最多显示 5 个 |
| 版本数   | 总制品数量                    |
| 部署按钮 | 进入部署对话框                |

### 6.3 一键部署

点击「部署」按钮，填写参数：

| 字段     | 说明                            | 示例                         |
| -------- | ------------------------------- | ---------------------------- |
| 镜像     | 自动填充，不可修改              | `appstore/happy_chat:V1.0.0` |
| 容器名称 | 自定义容器名                    | `my-happy-chat`              |
| 端口映射 | 逗号分隔，`宿主机端口:容器端口` | `8080:80,3306:3306`          |
| 环境变量 | 每行一个，`KEY=value`           | `MODE=production`            |

点击「拉取并启动容器」，后端自动完成：凭证认证 → `docker pull` → `docker create` → `docker start`。

### 6.4 容器管理

部署后在 **容器列表** 中管理容器：

| 操作 | 说明                             |
| ---- | -------------------------------- |
| 启动 | 启动已停止的容器（轮询确认状态） |
| 停止 | 停止运行中的容器（5 秒超时）     |
| 删除 | 强制删除容器（`docker rm -f`）   |

## 7. 完整使用示例

```text
1. docker login 192.168.41.227:8097
2. docker build -t happy_chat:latest .
3. docker tag happy_chat:latest 192.168.41.227:8097/staging-project/happy_chat:V1.0.0
4. docker push 192.168.41.227:8097/staging-project/happy_chat:V1.0.0
5. 联系管理员审核
6. 审核通过后，通过部署控制台拉取并部署：
   镜像: appstore/happy_chat:V1.0.0
   容器名称: my-happy-chat
   端口映射: 3000:3000
   环境变量: TZ=Asia/Shanghai
7. 在容器列表中启动/停止/删除容器
```

## 8. 最佳实践与安全

- 遵循语义化版本号，避免覆盖已发布版本。
- 使用 `.dockerignore`，避免敏感文件进入镜像。
- 使用专用、独立的镜像账号，尽量不与他人共享凭证。
- 定期更新登录密码（Docker 登录与部署控制台登录均受影响）。
- 不要把 Docker 登录凭证提交到代码仓库。
