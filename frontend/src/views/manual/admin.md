# 管理员使用手册

平台提供 Web 管理后台，供管理员对**应用商店**进行日常管理：项目管理、成员管理、用户管理，以及核心的**应用审核**（预发布 → 生产 的发布流程）。

## 1. 登录

打开浏览器，访问管理后台地址，使用管理员账号登录：

| 字段   | 说明       |
| ------ | ---------- |
| 用户名 | 管理员账号 |
| 密码   | 管理员密码 |

登录成功后可看到首页仪表盘与管理菜单。

---

## 2. 首页仪表盘

首页顶部展示平台核心指标卡片：

| 卡片     | 说明                         |
| -------- | ---------------------------- |
| 总应用数 | 平台项目总数                 |
| 总镜像数 | 所有镜像制品（Artifact）总数 |
| 总拉取量 | 所有镜像累计拉取次数         |
| 活跃项目 | 当前项目总数                 |

下方还提供 **热门下载 TOP 5**、**最新上架**、**项目分布**、**数据汇总** 等视图，方便快速了解平台运行情况。

---

## 3. 项目管理

进入 **应用管理 → 项目管理**。

### 3.1 创建项目

点击 **创建项目** 按钮，填写：

| 字段        | 说明                         |
| ----------- | ---------------------------- |
| 项目名称    | 项目唯一名称（用于镜像地址） |
| 公开 / 私有 | 选择项目的访问级别           |

### 3.2 查看与应用

- **查看仓库**：点击项目名称，进入其下的所有应用仓库列表。
- **查看制品**：点击仓库名称，查看该应用的版本列表（Tag、大小、Digest）。
- **拉取命令**：每个制品提供 Docker / Podman / nerdctl / ctr / crictl 五种拉取命令，可一键复制。
- **删除项目**：在操作列执行删除。

---

## 4. 成员管理

进入 **项目成员** 标签页，将用户添加到项目并分配角色：

| 角色       | 值  | 权限                              |
| ---------- | --- | --------------------------------- |
| 项目管理员 | 1   | 管理项目设置、成员，推送/拉取镜像 |
| 开发者     | 2   | 推送/拉取镜像                     |
| 访客       | 3   | 只读，可拉取镜像                  |
| 维护者     | 4   | 维护权限                          |

---

## 5. 用户管理

在 **系统管理 → 用户管理** 中创建用户。用户凭证用于：

- Docker 登录镜像仓库（开发者推送、拉取镜像）。
- 部署控制台登录。

建议为每个开发者 / 使用者单独创建账号，避免共享凭证。

---

## 6. 应用审核（核心流程）

平台采用 **预发布（staging）→ 审核 → 生产（production）** 的发布机制。开发者将镜像推送到预发布项目后，必须由管理员审核通过，镜像才会自动同步到生产项目，供用户拉取部署。

### 6.1 审核记录自动创建

当开发者向 **staging-project**（预发布项目）推送镜像时，镜像仓库会通过 Webhook 通知后端，后端自动创建一条审核记录：

| 项目     | 说明                                       |
| -------- | ------------------------------------------ |
| 触发条件 | 任意新镜像推送到 staging-project 下的仓库  |
| 自动填充 | 源项目、目标项目、仓库名称、Tag、Digest    |
| 初始状态 | 待审核（pending）                          |
| 去重机制 | 同一仓库 + 同一 Tag 的待审核记录只创建一条 |

> 前置条件：需为 staging-project 配置 Webhook，指向 `http://<后端地址>:3000/api/webhooks/harbor`，并配置 `webhook_secret`。

### 6.2 手动创建审核记录

管理员也可在 **应用管理 → 项目管理 → 应用仓库 → 制品详情** 中点击 **审核** 按钮手动发起审核：

1. 进入 **应用管理 → 项目管理**。
2. 点击项目名称进入 **应用仓库**。
3. 点击仓库名称查看 **制品列表**。
4. 在目标制品行点击 **审核**。
5. 弹窗中自动填充源/目标项目、仓库名、Tag、Digest。
6. 可选填写备注后提交。

### 6.3 审核列表

在 **应用管理 → 应用审核** 标签页，以表格展示所有审核记录：

| 字段     | 说明                               |
| -------- | ---------------------------------- |
| 源项目   | 镜像来源项目（staging-project）    |
| 目标项目 | 镜像目标项目（production-project） |
| 仓库     | 应用名称                           |
| Tag      | 版本号                             |
| 摘要     | 镜像 Digest                        |
| 状态     | 待审核 / 已通过 / 已拒绝           |
| 审核意见 | 管理员填写的审核意见               |
| 创建时间 | 审核记录创建时间                   |

**筛选**：支持按仓库名称模糊搜索、按状态筛选。

### 6.4 审核操作

对状态为 **待审核** 的记录：

**通过审核**

1. 点击 **通过**。
2. （可选）填写审核意见。
3. 确认后系统自动执行：
   - 调用镜像仓库 API 创建临时复制规则；
   - 触发复制任务，将镜像从 staging-project 复制到 production-project；
   - 等待复制完成（默认超时 30 秒）；
   - 清理临时复制规则；
   - 将审核状态更新为 **已通过（approved）**。
4. 提示「审核通过并已触发复制」。

**拒绝审核**

1. 点击 **拒绝**。
2. （可选）填写拒绝理由。
3. 状态更新为 **已拒绝（rejected）**，镜像不会进入生产项目。

**删除记录**：支持删除已完成的审核记录（软删除）。

> 技术原理：后端通过镜像仓库 REST API 动态创建临时复制策略（源 staging-project → 目标 production-project，按仓库名和 Tag 过滤），触发手动执行并等待成功（Succeed）后自动删除策略。这确保了只有审核通过的镜像才会进入生产环境。

## 7. 环境与复制配置

平台预设两个项目区：

| 项目                       | 用途                             | 推送权限       | 拉取权限 |
| -------------------------- | -------------------------------- | -------------- | -------- |
| staging-project（预发布）  | 开发者推送镜像、触发审核         | 开发者         | 管理员   |
| production-project（生产） | 审核通过后自动复制、用户拉取部署 | 仅通过复制规则 | 所有用户 |

镜像仓库复制规则需要配置 **本地 Registry 端点** 以实现项目间复制。生产项目建议设为 **公开**，方便普通用户拉取镜像。

后端配置位于 `backend/config/config.toml` 的 `[harbor]` 段：

| 配置项                     | 说明                                      |
| -------------------------- | ----------------------------------------- |
| `staging_project`          | 预发布项目名称（默认 `staging-project`）  |
| `production_project`       | 生产项目名称（默认 `production-project`） |
| `webhook_secret`           | Webhook 密钥，用于验证请求来源            |
| `replication_timeout_secs` | 等待复制完成的超时时间（默认 30 秒）      |

---

## 8. 运维与安全建议

- 为 staging-project 正确配置 **Webhook**（Push Artifact 事件），否则不会自动生成审核记录。
- 生产项目建议设为 **公开**（普通用户无需登录即可拉取）。
- 定期更换开发者凭证，避免长期共享密码。
- 私有项目注意访问控制，谨慎分配成员角色。
- 配置 `webhook_secret`，防止审核端点被恶意调用。
- 定期查看审核列表，及时处理待审核的镜像。
