# 管理员使用手册

平台提供 Web 管理后台，用于维护 **机器狗资源数据**（地图、模型、媒体、指令、配置、服务）以及平台自身的用户、角色、菜单、日志与安全配置。

> 园区、设备、任务、路线及设备接入已由 `business/` 独立业务服务承载，根后台不再提供对应菜单与接口。

## 1. 登录

打开浏览器访问管理后台，使用管理员账号登录：

| 字段   | 说明       |
| ------ | ---------- |
| 用户名 | 管理员账号 |
| 密码   | 管理员密码 |

登录成功后进入首页仪表盘，左侧菜单为一级平铺展示：首页、「系统管理」、地图管理、模型管理、媒体资源、指令管理、参数配置、服务管理。

> 密码连续输错达到上限、或超过密码有效期时会提示锁定/修改密码，按提示处理即可。

## 2. 首页仪表盘

首页展示四张统计卡片与一张图表：

| 区块     | 说明                                     |
| -------- | ---------------------------------------- |
| 模型数量 | `dog_model` 中未删除的模型条数           |
| 媒体数量 | `dog_media` 中未删除的媒体条数           |
| 指令数量 | `dog_command` 中未删除的指令条数         |
| 服务数量 | `dog_services` 中未删除的服务条数        |
| 数量统计 | 按「上周 / 本周」切换的四类资源柱状图    |

卡片上的百分比为 **周同比**（本周新增 vs 上周新增），折线为本周每日新增数量。

## 3. 通用列表操作

以下页面（地图、模型、媒体、指令、参数配置、服务）操作方式一致：

| 操作     | 说明                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 搜索     | 顶部查询表单，填写条件后点「搜索」，点「重置」清空条件并刷新                                               |
| 新增     | 右上角「新增」按钮，弹窗填写表单后提交                                                                     |
| 修改     | 表格行「修改」，弹窗中修改字段后提交                                                                       |
| 删除     | 表格行「删除」，二次确认后执行（**软删除**，对应业务记录不再展示）                                         |
| 分页     | 表格底部切换页码 / 每页条数，默认每页 10 条（服务管理为全量列表）                                          |
| 查询     | 顶部统一查询栏（与用户管理一致）：常用条件常显，点右侧箭头展开「更多条件」，点「搜索」查询、点「重置」清空 |
| 下拉条件 | 状态下拉等选项在所有页面保持一致（如指令状态 待下发 / 已下发 / 成功 / 失败）                               |

统一约定：

- 列表默认按 **创建时间倒序** 排列。
- 时间字段统一按 **北京时间（UTC+8）** 展示，格式 `YYYY-MM-DD HH:mm:ss`。
- 数字型字段（如文件大小）使用数字输入框，避免提交字符串导致接口报错。

### 3.1 数据权限（地图）

地图按 **创建者** 做行级隔离：普通用户只能看到、修改、删除自己创建的地图，访问他人数据返回「不存在」；管理员（内置角色 `sysadm`，角色编码 `110`）可查看和操作全部数据。「所属用户ID」由服务端根据登录 token 自动写入，无需也不允许在表单中填写。

模型、媒体、指令、参数配置、服务为共享资源，不做用户级隔离。

## 6. 指令管理

记录机器狗指令及其执行结果（设备下发由 `business/` 业务服务负责，后台只维护指令档案）。

| 字段     | 说明                                                                 |
| -------- | -------------------------------------------------------------------- |
| 指令名称 | **必填**                                                             |
| 指令类型 | 指令分类                                                             |
| 指令参数 | 下发的参数（JSON 字符串）                                            |
| 目标设备 | 目标设备标识（文本，可留空）                                         |
| 状态     | 默认 `pending`（待下发），可维护为 `sent` / `success` / `error`      |
| 返回值   | 执行结果                                                             |
| 任务 ID  | 关联任务主键（数字，可留空）                                         |
| 创建时间 | 记录创建时间                                                         |

查询条件：指令名称、指令类型、状态（下拉：待下发 / 已下发 / 成功 / 失败）；「更多条件」中还支持设备 ID、任务 ID 与创建时间范围。

## 9. 地图管理

地图管理以「地图包」的方式维护，新增时直接上传 `.zip` 地图包（落盘到 `data/device_uploads/maps/`）。

| 字段             | 说明                                    |
| ---------------- | --------------------------------------- |
| 地图名称         | **必填**，地图显示名称                  |
| 地图类型         | 下拉选择：离线地图 / 在线地图           |
| 基线版本         | 版本号，例如 `v1.0`                     |
| 坐标系 frame_id  | 地图坐标系标识                          |
| CRS              | 坐标参考系说明                          |
| 文件名称         | 上传的地图包文件名（自动写入）          |
| 文件格式         | 地图包格式，目前仅支持 `zip`            |
| 文件大小（字节） | 地图包大小（自动写入）                  |
| 描述信息         | **必填**，地图说明                      |
| 创建时间         | 记录创建时间                            |

| 操作   | 说明                                                                     |
| ------ | ------------------------------------------------------------------------ |
| 新增   | 「新增」→ 填写地图名称 / 类型 / 描述 → 「选取文件」上传 `.zip` → 确认    |
| 修改   | 弹窗中可改名称 / 类型 / 描述；如需更换地图包，重新上传 `.zip` 后确认即可 |
| 发布   | 将草稿 / 部分标定版本推进为「已发布」，并记录发布时间                    |
| 新版本 | 基于当前版本派生下一个版本并立即发布                                     |
| 删除   | 二次确认后软删除记录（原地图包文件保留在磁盘上）                         |

> 查询条件：地图名称、地图类型（下拉）、基线状态（下拉）、文件名称；「更多条件」中可按创建时间范围过滤。

> 上传后由后端解析包内 `model.pgm` / `model.yaml`，回写分辨率、原点、栅格尺寸与 SHA-256（`map_hash`），表单值与包内容冲突会被拒绝。

## 11. 常见问题

**列表里没有刚创建的数据**
：页面按创建时间倒序并分页展示，确认查询条件是否残留；确认提交时接口返回 `code = 10200`。

**删除后数据还在数据库里**
：资源类数据统一使用软删除（`is_deleted = 1`），接口与页面都不会再展示该记录。

**首页图表没有数据**
：统计来自 `dog_model` / `dog_media` / `dog_command` / `dog_services` 的真实记录，新增对应资源后即可看到数据。

**园区 / 设备 / 任务 / 路线去哪了**
：这些业务已迁移到 `business/` 独立服务（默认端口 3100），请在独立控制台维护。
